# 통치자의 아이(육아) 설계서 (2026-10-27 초안, 다음 업데이트)

외부 건의: "통치자와 배우자 사이에서 무작위로 새 지도자가 태어나게 — CK3 처럼 아이를 시뮬레이션".
스텔라리스 지도자는 어른으로만 존재하고 어린 시절이 없다 → **태어나서 성인이 될 때까지는 앱이 키우고**, 성인식 때 모드가 실제 지도자를 만든다(`create_leader`).
사용자 확정 사항은 ★. 2026-10-27 모든 제안 확정 → 구현 시작.

## 1. 확정 사항
| 항목 | 결정 |
| --- | --- |
| 대상 ★ | **통치자 부부만**(NPC 지도자 부부는 아이 없음) |
| 배우자가 비서 ★ | 아이 없음(안드로이드) |
| 기본 확률 ★ | 해마다 **3%** |
| 상한 ★ | **배우자마다 2명**, 그리고 **통치자 한 명당 모두 합쳐 8명**(성인이 된 아이도 셈, 2026-10-27) |
| 확률 올리기 ★ | 배우자와의 1:1 통신에서 **플레이어가 그 장면을 묘사하면** 그해 확률이 오른다(합의 문구 필요 없음) |
| 오른 확률 | 그해 **30%**(제안, 배우자마다 해마다 한 번만 적용) |
| 수위 ★ | 앱은 막거나 거르지 않는다. 배우자 대화 프롬프트에 수위 지시(암전 등)를 넣지 않는다 — 플레이어 책임, 고른 AI 서비스의 판단 |
| 나이 ★ | 진짜 나이로 센다. **게임 시간 18년 뒤 18세**로 등장 |
| 부모 나이 ★ | 일단 제한 없음(보류) |
| 제안 확정 ★ | 묘사한 해 30%, 양육 사건 6번, 사건 답 기한 1년, 청소년 대화 해마다 4번, 「부모를 잃음」 사건, 세습 정부 「후계자로 세우기」 — 모두 그대로(2026-10-27) |
| 육아 깊이 ★ | **깊게** — 단계별 양육 사건(틀 문장·선택지) + 청소년기부터 아이와 직접 대화(이때만 LLM) |
| 성인식 ★ | **바로 우리 지도자로**(지도자 수 상한에 셈) |

## 2. 흐름
1. **탄생 판정(매년)**: 통치자가 살아 있는 배우자(비서 아님)와 결혼 중이면, 배우자마다 그해 확률(3% 또는 30%)로 아이가 생긴다. 배우자마다 2명 또는 통치자의 아이가 모두 합쳐 8명이 차면 더 없다.
   - 판정 시점: 해가 바뀌는 첫 월간 상황(onGameSnapshot). 게임 명령 없음(앱 계산만).
   - 그해 「묘사함」 표시가 있으면 30%, 판정 뒤 표시는 지운다.
2. **임신 → 출산**: 판정된 해에는 「아이를 가졌습니다」 소식, 9개월 뒤 출산(게임 날짜). 출산 소식은 연대기·신문(틀 문장).
3. **성장(앱)**: 영유아(0~2) → 어린이(3~11) → 청소년(12~17). 나이는 생일과 게임 날짜로 계산.
4. **양육 사건(틀 문장, LLM 없음)**: 2~3년에 한 번씩 그 나이에 맞는 사건 + 2~3개 선택지. 선택이 「성향 점수」로 쌓인다(4장).
5. **청소년기 대화(LLM)**: 12세부터 아기방에서 아이와 1:1 대화. 인물 1:1 통신과 같은 방식(말투·기억). 1년에 몇 번까지(제안 4번).
6. **성인식(18세, 모드)**: 쌓인 점수로 직업·특성 2개를 정하고 `create_leader` 로 우리 지도자로 만든다. 연대기·신문·알림.

## 3. 「묘사함」 판단
- 배우자와의 1:1 통신(persona-app `personaSay`)에서 AI 가 이미 돌려주는 JSON 에 칸 하나를 더한다: `"intimate": true|false` — 이번 대화에서 두 사람의 육체적 친밀함이 묘사되었는가.
- 그 인물이 통치자의 **배우자일 때만** 이 칸을 묻는다(다른 인물 대화에는 넣지 않음). **AI 호출이 늘지 않는다**(같은 답에 칸만 추가).
- true 가 한 번이라도 나오면 그 배우자의 「올해 묘사함」 표시. 같은 해 여러 번이어도 한 번.
- 수위 지시 없음(1장). 앱은 플레이어 글을 그대로 넘긴다.

## 4. 양육 사건과 성향 점수
- 점수 축 3개 = 성인식 때 직업: **관료(official)·과학자(scientist)·사령관(commander)**. 가장 높은 축이 직업. 같으면 무작위.
- 사건마다 선택지 2~3개, 선택지마다 축 점수 +1~+2 와 **특성 후보** 하나(예: 「별 지도를 밤새 본다」 → 과학자 +2, 후보 「호기심 많은」 계열).
- 성인식 특성 2개(구현 2026-10-27, 게임 4.x common/traits 확인): 선택지마다 「성향 꼬리표」 하나 → 가장 많이 나온 꼬리표의 **세 직업 공통 1레벨 특성**(대담 → eager, 호기심 → adaptable, 강인 → resilient, 사교 → politician, 고집 → stubborn, 우울 → melancholic, 외톨이 → reclusive) + **직업 1레벨 특성** 하나(사령관 aggressive·cautious·unyielding·trickster·skirmisher·engineer / 관료 bureaucrat·righteous·shipwright / 과학자 carefree·roamer·archaeologist·meticulous, DLC 없이 쓰는 것만). 고르는 순서는 아이 ID 로 정해 다시 계산해도 같다. 이름은 게임 지역화 그대로.
- 사건 나이: 1(첫걸음)·4(궁 안의 다툼)·7(가정교사)·10(몰래 나간 밤)·13(첫 공식 행사)·16(진로). 앞 사건에 답하기 전에는 다음 사건이 오지 않는다.
- 사건 수: 아기 1 · 어린이 3 · 청소년 2 = **6번**(제안). 사건 문장은 한/영 틀 문장으로 미리 쓴다(자리 ~30개, 종족 이름·부모 이름·행성 이름 끼움).
- 놓친 사건: 일정 기간(제안 1년) 안에 고르지 않으면 「부모가 바빴다」로 처리(점수 없음).
- 부모의 죽음: 아이에게 기록이 남고, 대화 말투와 성인식 특성 후보에 영향(제안: 「부모를 잃음」 사건 1개 추가).
- 게임 효과는 **성인식 전까지 없다**(이야기만, 비서 이벤트와 같은 원칙).

## 5. 청소년기 대화
- 아기방에서 아이 자리를 누르고 「대화하기」. 인물 1:1 통신과 같은 틀(말투는 성향 점수·부모·사건 기억에서).
- ~~대화도 성향에 조금 반영~~ → 폐기(2026-10-27): 대화는 성향에 넣지 않고, 직업은 「공부」로 고른다(10-3).
- 해마다 4번까지(제안). 이 대화만 LLM 을 쓴다.

## 6. 성인식(게임)
- 구현(2026-10-27): 모드 파일 없이 **콘솔 effect 한 줄**(결혼 특성 명령과 같은 방식, `src/children.ts childAdultCommand`). 아래는 그 내용:
  - 부모 지도자(sllm_lid = PARENT)의 종족으로 `create_leader = { class = <CLASS> species = <부모 종족> name = "<NAME>" gender = <GENDER> skill = 1 set_age = 18 traits = { 0 = <TRAIT1> 0 = <TRAIT2> } randomize_traits = no }` (4.4.5 효과 설명서 확인: name·species·class·skill·set_age·traits·gender·randomize_traits).
  - 종족 ★(2026-10-27 사용자): **엄마(여성 부모)의 종족 60% · 아빠(남성 부모) 40%**(게임 `gender` 로 확인, 아이 ID 로 정해 늘 같음). 그 성별의 부모가 없으면(동성 부부·성별 없는 종족) 배우자 → 통치자 순, 둘 다 없으면 나라의 주 종족. 같은 성별 부모가 둘이면 배우자 쪽.
  - 이름: 그 종족의 게임 이름 표(앱의 namegen, 인물 이름 규칙)에서. **성 물려받기는 게임에서 시험 필요**(name 문자열에 성을 넣는 방식).
  - 아이마다 한 번만(국가 변수 `sllm_ch_<아이>`), 만든 지도자에게 바로 `sllm_lid`(명단 이벤트와 같은 `sllm_lid_next`), 회신 `SLLM:CHILDADULT … status=applied lid=`. 회신을 놓치면 다음 달 `duplicate` → 명단의 같은 이름으로 잇는다.
  - 종족: 부모 지도자에서 `species = { save_event_target_as = sllm_ch_species }`, 못 찾으면 `owner_main_species`.
- 만든 뒤: 앱의 지도자 명단(sllm_people)에서 그 lid 를 「통치자의 아이」로 표시, 부모·어린 시절 기억이 그 인물의 1:1 통신 기억으로 이어진다.
- 세습 정부(제안, 미정): 「후계자로 세우기」 단추 → `set_heir`(4.4.5 확인).

## 7. 화면 — 개인실의 「아기방」(2026-10-27 사용자 제안)
- 개인실(private-rooms: 복도·개인실·독서실·전시실·비서실)에 **방 하나 「아기방」**을 더한다. 첫 아이가 생기면(임신 소식부터) 개인실에 아기 소품 아이콘이 나타나고, 누르면 아기방으로 간다. 아이가 없으면 소품도 없다.
- ★(2026-10-27 사용자): 아기방 **그림은 하나**(`ui/assets/private-rooms/nursery/nursery.png`). 개인실의 요람을 누르면 **아이 목록부터** — 「누구를 보러 가시겠습니까?」(배우자별로 묶음, 고를 일이 있는 아이 표시) → 고른 아이 한 명이 아기방 그림 위에 보인다. 아기방 안에서 「다른 아이 보러 가기」로 다시 목록.
- 단계마다 소품이 바뀐다 — 아기 = 요람, 어린이 = 작은 침대·장난감, 청소년 = 책상. 고를 일이 있으면 아이를 보러 가자마자 패널이 열린다.
- 자리를 누르면 그 아이의 패널: 이름·나이·부모, 성장 기록, 지금 온 양육 사건 선택지, 성향 축 3개 막대, 청소년이면 「대화하기」.
- 성인이 된 아이는 자리에서 빠지고 「다 자란 아이들」 기록에 남는다(그 뒤로는 연락처의 우리 지도자).
- 알림: 임신·출산·사건 도착·성인식 → 「아기방으로 가기」.
- 개인실 화면 규칙(홀로그램 버튼·테마)을 따른다. 한/영 문구 함께, 언어 팩 규칙(L()) 준수. 게임 특성 이름은 게임 지역화.
- 그림 ★(2026-10-27 사용자): **방과 실루엣 모두 GPT 가 그린다** — 의뢰 `docs/NURSERY_ART_GPT_TODO_20261027_KO.md`, 프롬프트 `docs/NURSERY_ART_PROMPTS_20261027.json`(배경 `nursery.webp` 1장 + 실루엣 `sil-<baby|child|teen>-<m|f>-<1|2|3>.webp` 18장). 그림이 오기 전에는 홀로그램 선 그림.
- 아이 모습 ★: **실루엣만**(얼굴 없음). 단계 영유아(0~2세)·어린이(3~11세)·청소년(12~17세) × 성별 × 체격 3(가냘픔·보통·다부짐)을 **모두 따로 그린 그림**으로 구별한다(늘이고 줄이지 않음). 체격은 아이마다 ID 로 정해 자라도 같다. 성인식 뒤에는 게임 지도자 초상화.

## 8. 제외·조건
- 게슈탈트(기계 지성·군체) 제국: 기능 없음(비서와 같은 이유).
- 배우자가 비서: 아이 없음 ★. 배우자가 죽거나 이혼하면 새 아이 없음(있는 아이는 그대로).
- 통치자가 바뀌면: 아이는 「앞 통치자의 아이」로 남고 계속 자란다. 새 통치자의 결혼은 새 아이 판정.
- 철인 모드 미지원(기존 원칙).

## 9. 저장·연결
- 앱: `src/children.ts`(규칙: 판정·나이·단계·점수·성인식 명령), `src/features/children-app.ts`(저장 `userData/children/<세이브>.json`, 월간 판정, IPC childList·childAnswer·childRename·childHeir·childTalkOpen/Say/End), `src/app/children-hooks.ts`(persona-app ↔ 아이 기능 다리, 순환 가져오기 방지), `ui/nursery.js`·`nursery.css`(아기방) + `ui/private-rooms.js` 의 「아기방」 방·바닥 홀로그램 요람, 그림 `ui/assets/private-rooms/nursery/`, 자체 검사 `src/children-check.ts`(28개), 로그 자리 SLOT.CHILDREN 219.
- 모드: 파일 없음(콘솔 effect). 앱 문구는 한/영 L().
- 기존 연결: persona-app(배우자 대화 → intimate), romance(결혼 상태·배우자), people(명단·종족), namegen(이름), chronicle·신문(소식).
- AI 호출: 배우자 대화는 늘지 않음(칸만 추가). 청소년기 대화만 새 호출. 나머지는 모두 틀 문장.

## 10-2. 대화·초상화(2026-10-27 사용자)
- 대화: **영유아(0~2세)는 말을 못 함**(대화 단추 대신 안내), **어린이(3~11세)도 대화** — 아이 말투로 한 문장(많아야 두 문장), 청소년(12~17세)은 1~3문장. **대화 횟수 제한 없음**(2026-10-27 사용자, 해마다 4번 규칙 폐기).
- 대화 화면(GPT 손봄): 아기방 배경을 흐리고 아이 대화 그림을 크게, 아래 대사창. 그림 순서 = 플레이어가 고른 초상화 → `talk-<child|teen>-<m|f>-<1|2|3>.webp` → 실루엣. (청소년 대화 그림 6장은 GPT 완성, 어린이 대화 그림은 아직 없음 → 실루엣.)
- **플레이어 초상화**: 아이 패널 「🖼 초상화 넣기/바꾸기」·「기본 실루엣으로」. 기존 지도자 개인 초상화와 같은 저장(키 `person:<세이브>:n:child-<아이>`). 아기방 자리·대화 화면에서 실루엣 대신 쓰고, **성인식 때 그 지도자 초상화로 옮겨 쓴다**(이미 지도자 초상화가 있으면 그대로).

## 10-3. 공부(2026-10-27 사용자)
- 「누구를 보러 가시겠습니까?」 목록에서 어린이·청소년마다 아래에 **직업 아이콘 3개(관료·과학자·사령관) — 「어떤 공부를 시키겠습니까?」**. 아이 패널에도 같은 줄.
- 고르면 성인식 직업이 그것(다시 누르면 취소). 고르지 않으면 양육 사건 성향이 가장 높은 직업(자동).
- **대화는 성향에 넣지 않는다**(대화 끝 요약은 아이의 기억 한 줄만).

## 11. 가족(2026-10-27 사용자 확정)
- **가족관계 장부**: 아이 장부에서 부모·자녀·형제자매(배우자가 다르면 이복)를 읽는다. 집무실 인물 카드에 「가족」 칸(부모·자녀·형제자매, 고인 표시). 앱: `familyInfo`.
- **대화가 가족을 안다**: 1:1 통신 프롬프트에 `[Your family]` 한 줄 — 배우자는 자기 아이들(나이·단계), 성인이 된 아이는 부모·형제자매를 안다. AI 호출은 늘지 않음.
- **게임 가족 특성** 「통치자의 자녀」(`sllm_trait_ruler_child`): 성인식 때 붙음, **지도자 경험치 획득 +15%**(`species_leader_exp_gain`).
- **가족의 죽음**: 성인이 된 아이가 죽으면 살아 있는 부모(통치자·배우자) 지도자에게, 부모가 죽으면 성인이 된 아이에게 「가족을 잃은 슬픔」(`sllm_trait_family_grief_<직업>`, 직업 효과 −10%, NPC 사별 슬픔과 같은 크기). **3년 뒤 앱이 뗀다**(제안). 그 인물의 기억에도 한 줄. 성인식 전 아이는 기존 「부모를 잃다」 사건.
- 모드 파일: `common/traits/sllm_family_traits.txt`, 문구 `sllm_family_l_english/korean.yml`(다른 언어는 대체 문구 파일에 합침). 게임 명령 회신 `SLLM:CHILDTRAIT`.
- 개발자 도구(설정 → 개발자 도구): 「아이 바로 태어나기」(확률·임신 건너뜀) · 「아이 1년/6년 키우기」(나이만 당기고 이번 달 판정 실행) — 게임에서 성인식까지 빨리 시험.

## 10. 게임에서 확인할 것
- 콘솔 effect 안의 `create_leader = { … effect = { … } }` 에서 `root.sllm_lid_next` 로 번호가 붙는지, `\[This.sllm_lid]` 가 회신에 찍히는지.
- `species = event_target:sllm_ch_species`(부모 지도자 종족)·`owner_main_species`(대신) 둘 다.
- 한글 이름 문자열이 콘솔로 그대로 들어가는지.
- `create_leader` 의 `name = "<문자열>"`(성 포함)이 그대로 쓰이는지.
- `species = <부모 지도자 scope>.species` 또는 event_target 으로 종족 지정이 되는지.
- `traits = { 0 = <특성> }` 가 직업과 맞지 않는 특성일 때의 동작(앱이 직업별 목록에서만 고르므로 원칙상 없음).
- `set_heir` 가 세습 정부에서 그 지도자를 후계자로 세우는지.
- 「통치자의 자녀」·「가족을 잃은 슬픔」 특성 이름·아이콘·효과가 게임에 보이는지, 3년 뒤 떨어지는지.
