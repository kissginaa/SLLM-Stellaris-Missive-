# 게임 안 확인 목록 (2026-10-26 작업분, 다음 업데이트 전)

오늘 만든 기능 가운데 **작업 공간 자체 검사만 통과했고 실제 게임에서는 아직 돌려 보지 않은 것**입니다.
모두 Stellaris 4.5.2 + 집 PC 개발 모드(tester-mod) 기준. 확인한 항목은 ☐ → ☑ 로 바꾸고, 문제가 있으면 줄 아래에 적어 주세요.

## 0. 준비
- 앱: `새 폴더\app\SLLM-Tester\start_app.bat` 로 켠다(src 가 새로 빌드됨).
- 게임: **새로 실행**(새 모드 파일 — 이벤트 체인·온액션·수정자·현지화 — 는 게임이 켜질 때만 읽음). 런처에서 SLLM 개발 모드가 켜져 있는지.
- 게임 로그: `문서\Paradox Interactive\Stellaris\logs\game.log` 에 `SLLM:` 줄이 찍힌다. 오류는 같은 폴더 `error.log`.
- 콘솔(`~`)에서 시험용 명령은 앱이 보내는 것과 같다. 아래 「직접 시험」 명령은 손으로 넣어 볼 때.
- 세이브 조건: 약탈자(잠든 약탈자)와 연락 중 + 이웃 제국 2곳 이상 + 가능하면 전쟁 하나. 그레이트 칸 시험은 그레이트 칸이 각성한 세이브가 있으면 그걸로(없으면 나중에).

## 1. 국경·외교 사정 (frontier.ts, 모드 추가 없음)
| ☐ | 확인 | 방법 | 기대 결과 |
| --- | --- | --- | --- |
| ☐ | 이웃 판정 | 이웃 제국과 외교 대화 한 마디 | game.log 에 `SLLM:FRSYS … side=us/them` 줄 + `SLLM:FR_END … nb=1`. AI 가 실제 국경 성계 이름을 말함 |
| ☐ | 먼 제국 | 국경이 안 닿는 제국과 대화 | `nb=0`, AI 가 국경 이야기를 하지 않음 |
| ☐ | 점령 | 전쟁 중 점령한 성계가 있을 때 대화 | `side=lost/taken` 줄 이름이 실제 점령 성계와 같음 |
| ☐ | 영유권 | 상대 성계에 영유권을 걸어 둔 상태 | `side=pclaim`(우리 주장), 상대가 걸었으면 `side=xclaim` |
| ☐ | 공동의 적 | 같은 적과 함께 전쟁 중인 제국 | `side=foewar` 에 그 적 이름 |
| ☐ | **intel 방향** | `FR_END` 의 `in=` 값 | 상대가 우리를 아는 정도(0~4). 게임 화면의 「정보 수준」과 반대로 나오면 frontier.ts 의 intel 줄에서 who 를 바꿔야 함 |
| ☐ | 신뢰·명분·종속·사절·공동체 | `FR_END` 의 tr/cbx/cbp/sub/ex/ep/gx/gp | 게임 외교 화면과 맞음 |
| ☐ | 콘솔 길이 | 세 줄 명령이 잘리지 않음 | 세 줄 모두 실행(로그에 FRSYS·FR_END 둘 다). 잘리면 error.log 에 구문 오류 |
| ☐ | 칸 후계국 | 디아도코이·새 칸국이 있는 세이브에서 대화 | `FR_END … kx=1~3`, AI 가 「그레이트 칸의 후계국」으로 말함 |
| ☐ | 다른 기능 | 대사관 전문·첩보 보고·대사와 대화·전쟁 선언문·규탄 성명·신문·라디오 | 맞닿은 성계·영유권·점령 이야기가 실제와 맞게 들어감(첩보 보고만 상대의 명분·신뢰) |

## 2. 약탈자 ②③ (sllm_marauder_deals.txt — 모드 추가)
| ☐ | 확인 | 방법 | 기대 결과 |
| --- | --- | --- | --- |
| ☐ | 상태 읽기 | 습격 예고(marauder.101)를 받은 뒤 그 약탈자와 통신 | `SLLM:MRD/;/op=status … raid=1 pow=0~4` |
| ☐ | **전력 방향** | `pow` 값과 실제 함대 전력 | 우리가 강할 때 3·4. 반대로 나오면 relative_power 방향 수정 |
| ☐ | 위협 | 우세일 때 「함대를 보내겠다」로 위협 → 제안 수락 | `op=withdraw status=applied`, 습격 함대가 사라지고 raid_cooldown |
| ☐ | 돌리기 | 다른 제국으로 돌려 달라 → 수락 | 에너지 차감, `status=applied`, 대상 제국 쪽으로 새 습격 함대(marauder.33) |
| ☐ | 용병 흥정 | 할인 약속 → 게임 「용병 고용」으로 그 부족 용병 고용 | 다음 달 `SLLM:MRCREF … amt=` 와 에너지 환급 알림 |
| ☐ | 대상 추천 | 습격당하지 않을 때 약탈자와 통신 → 「누굴 털면 좋겠나」 | 발언 전 `SLLM:MRDT … idx= f= tf=` 줄(통신 중인 제국마다)과 `op=status … free=1`. 약탈자가 경쟁국·약한 곳을 골라 말함 |
| ☐ | **tf 방향** | `MRDT` 의 `tf` | 그 제국 함대가 약탈자보다 셀 때 3·4. 반대로 나오면 sllm_mrd_status 의 relative_power 방향 수정 |
| ☐ | 습격 의뢰 | 추천받은 곳에 의뢰 → 수락 | `op=hire status=applied`, 에너지 차감, 대상 쪽 습격 함대(marauder.33). 그 약탈자가 습격·쿨다운 중이면 `status=busy` |
| ☐ | 의뢰·돌리기 가격 | 경쟁국 하나·경쟁국 아닌 곳 하나에 의뢰(돌리기도) | 경쟁국은 3000 근처, 아닌 곳은 4500 근처(제안 문구에 「1.5배」). `MRDT` 의 `f` 에 경쟁국이면 1 이 더해짐 |
| ☐ | 문법 | error.log | `add_resource … mult = 변수`, `round_variable_to_closest`, `scopes = { from = … }` 오류 없음 |

## 6. 외교 거래 (sllm_deals — 모드 추가, docs/DIPLO_DEALS_DESIGN_KO.md)
| ☐ | 확인 | 방법 | 기대 결과 |
| --- | --- | --- | --- |
| ☐ | 거래판 읽기 | 일반 제국과 통신 → 「거래 제안」 | `SLLM:DEALX`(상대 창고·월수입)와 `SLLM:DEALCTX … ok=1`, 거래판의 창고·월수입이 게임과 같음(큰 수가 `12.3K` 처럼 찍혀도 읽힘) |
| ☐ | **국력 방향** | 거래판의 「우리가 우세/약함」 | 게임 외교 화면의 상대 평가와 같은 방향. 반대면 sllm_deal_ctx 의 relative_power 방향 수정 |
| ☐ | 신뢰 | 거래판 「신뢰」 | 게임 외교 화면의 신뢰 값 구간과 맞음 |
| ☐ | 한 번 주고받기 | 합금 50 ↔ 에너지 200 같은 거래 → 수락될 때까지 | `SLLM:DEAL … op=apply status=applied`, 양쪽 창고가 실제로 바뀜 |
| ☐ | 경쟁 해제·국경 | 상대가 우리를 경쟁국으로 둔 상태에서 「경쟁 관계 해제」 | 수락 뒤 경쟁 관계가 풀림(end_rivalry). 국경 개방은 기존 효과 |
| ☐ | 조공 평화 | 서로 전쟁 중 → 「종전 넣기」 + 상대가 매달 에너지 | 종전 처리 + 다음 달부터 `op=pay status=paid`, 우리 창고 증가 |
| ☐ | 미납·파기 | 우리가 매달 지급을 약속하고 창고를 비움(두 달) | 두 번째 달에 「약속을 어겼습니다」 알림, 상대 의견에 「약속을 어김 -50」, 연대기·신문 |
| ☐ | 갈고리 | 첩보 보고서에서 확인된 비밀(전쟁 명분·공격 계획 등)이 나옴 | 「약점을 쥐었습니다」 알림, 거래판에 「갈고리 쓰기」(+30) |
| ☐ | 참전 요청(우리→동맹) | 우리가 전쟁 중, 방위 조약 상대에게 「우리 전쟁에 참전」 | 동맹 +25. 수락이면 그 제국이 우리 전쟁에 들어옴(join_war) |
| ☐ | 참전 요청(동맹→우리) | 방위 조약 상대가 방어 전쟁에 들어감 | 다음 달 `SLLM:DEALAW … idx=` + 알림, 거래판 맨 위 요청. 참전 = join_war, 거절 = 「참전 요청을 거절함 -30」 + 신문 |
| ☐ | AI 말투 | 제안 뒤 대화창 | AI 가 정해진 결과(수락/거절)대로 한두 문장 |
